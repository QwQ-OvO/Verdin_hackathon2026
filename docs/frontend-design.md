# 前端设计：真实工作中的学习闭环

## 目标与范围

前端围绕一项真实工作展示两个视角：主管确认分工并审核，新人完成被预留的关键判断。MVP 覆盖一个岗位能力、一个任务、一个新人和一位主管。岗位探索、跨企业匹配、长期职业规划暂不进入主流程。

相关场景与角色见 [User Story](./user-story.md)。页面必须让人看清任务来自哪里、为什么保留某项判断、谁确认分工，以及谁批准最终业务结论。

## 导航结构

按角色显示待办任务列表。列表可作为入口组件，无需先建设复杂仪表盘。

| 页面 | 主要使用者 | 路径建议 | 核心动作 |
| --- | --- | --- | --- |
| 新建任务与分工确认 | 主管 | `/manager/tasks/new`、`/manager/tasks/:id/assignment` | 录入任务，查看逐步骤建议，确认或改判 |
| 任务工作台 | 新人 | `/learner/tasks/:id` | 阅读材料，引用原文，提交首次判断 |
| 提示与修订 | 新人 | `/learner/tasks/:id/revision` | 请求分级提示，查看提交后检查，解释修订 |
| 审核与能力证据 | 主管 | `/manager/tasks/:id/review` | 对照版本与证据，反馈，批准或退回 |

## 页面 1：新建任务与分工确认

### 输入

- 任务标题、来源、业务背景、截止时间、审核人。
- 目标能力，例如“从零散反馈中识别问题模式并说明依据”。
- 业务风险、允许访问的数据、是否允许新人参与、最终结论的使用范围。
- 任务材料或脱敏反馈。演示材料若为模拟数据，界面应明确标注。

### 输出与交互

系统把任务拆为“整理材料”“识别问题模式”“选择调查重点”“批准结论”等步骤，对每步展示建议负责人、理由和风险标记。主管可修改负责人；改判时填写简短原因。确认后生成新人任务。

在建议旁单独展示**学习安排**与**执行权限**：例如新人可以提出调查建议，但不能批准验证或风控规则调整。缺少访问权限或审核人时，阻止确认不合规分工并指出原因。

## 页面 2：新人任务工作台

- 展示任务目标、截止时间、需要本人形成的判断、主管的审核要求。
- 展示经 AI 整理的反馈，同时保留原文、反馈 ID 和每项整理结果到原文的映射。新人可以查看未经合并的反馈。
- 提供问题模式、两个优先调查方向、理由和原始反馈引用的结构化输入。
- 首次提交前不显示 AI 的分类、优先级或参考答案。页面也不预取这些内容。
- 首次提交后显示提交时间和只读版本，后续修改进入新版本。

若允许提交前求助，只提供不透露结论的问题式提示，并在提交处标注其提示使用情况。首次判断不能被描述为“完全独立”而隐藏已用提示。

## 页面 3：提示与修订

首次判断保存后开放。按需提供三级帮助：

1. 反思问题：提醒新人比较反馈所处阶段或证据差异。
2. 具体线索：指出值得重新检查的反馈范围，不给出最终分类。
3. 提交后证据检查：指出可能遗漏、矛盾证据和待核实假设。

显示首次判断与当前草稿的差异，要求新人说明“为什么改变判断”。提示记录可供新人和主管查看，不用提示次数作为单一能力评分。

## 页面 4：审核与能力证据

- 并排或按时间线展示首次判断、提示、修订、原始证据与主管反馈。
- 主管可批准业务结论或退回修改；退回后保留现有版本，重新提交产生新版本。
- 主管记录判断质量、主要遗漏、所需帮助和审核时间，并确认下一项任务的支持建议。
- 分开显示“业务交付状态”和“能力证据状态”。一次批准代表本次结论可使用，不代表新人已掌握能力。

## 关键界面状态

| 任务状态 | 新人可见内容与动作 | 主管可见内容与动作 |
| --- | --- | --- |
| 待确认分工 | 无任务入口 | 查看建议、改判、确认 |
| 执行中 | 材料、背景、允许的提示；提交首次判断 | 查看任务进度，不查看未提交草稿 |
| 首次判断已提交 | 只读首次版；请求提示与修订 | 查看首次版和已用提示 |
| 待审核 | 查看提交版本与状态 | 审核、批准或退回 |
| 已批准 / 已退回 | 查看审核意见 | 查看完整记录与能力证据 |

前端根据后端返回的状态和允许动作渲染按钮；权限与 AI 内容限制由后端执行。

## MVP 验收重点

1. 主管能理解并确认逐步骤分工，能够说明系统为什么把关键判断留给新人。
2. 新人能从整理结果追溯原始反馈，并提交带证据的首次判断。
3. 首次判断前，页面及网络响应均不包含 AI 的结论。
4. 主管能查看首次版、提示、修订及最终结论的完整轨迹。
5. 页面明确区分学习参与、业务批准和能力掌握。
